# Вариант 54. Слияние двух распределённых отсортированных последовательностей

## Условие

Профиль сети — S(8).

Процессы 0,…,3 хранят последовательные блоки по N чисел первой отсортированной
последовательности, процессы 4,…,7 — второй. Каждая последовательность целиком
неубывает, включая границы блоков.

Корень 0 должен получить отсортированное слияние всех 8N чисел с сохранением
кратностей. Требуется MPI-программа точка-точка с запросами блоков или частей
по необходимости. Исходные блоки сохраняются у владельцев, итоговый массив
выделяется корню.

Дополнительные буферы элементов последовательностей сверх исходного и итогового
массивов занимают не более 2N чисел на процесс.

Обязательные сценарии:

1. Непересекающиеся диапазоны.
2. Полное чередование значений.
3. Равные элементы на границах блоков.

В анализе нужно показать выбор следующего элемента и переход между владельцами
блоков. Оценить запросы, полезные данные, рабочую память и полное время
для выбранного способа слияния.

## Общая модель, существенная для варианта

- Любая пара процессов может обмениваться напрямую, но на всей шине одновременно
  передаётся только одно сообщение. Аппаратного широковещания нет.
- Стоимость сообщения длиной m байт: τ(m) = 100 + m условных единиц.
- Локальные вычисления, чтение и запись памяти имеют нулевую модельную стоимость.
- В длину сообщения входят все явно передаваемые поля протокола.
- int32, ранг, счётчик и длина занимают по 4 байта.
- Каждый явный запрос, подтверждение или другой сигнал учитывается отдельно.
  Пустое сообщение стоит 100 условных единиц.
- Для каждого типа сообщения нужны состав, длина, источник, получатель, тег
  и условие выдачи. Известные обеим сторонам поля можно не передавать.
- Готовые передачи обслуживаются по модельному времени готовности; при равенстве
  — по (источник, получатель, тег, локальный номер сообщения), с соблюдением
  программного порядка вызовов.
- Все участники начинают в момент 0. Барьеры после каждого шага не подразумеваются.
- Внутри алгоритма используются точечные обмены. Коллективные операции
  для подготовки и проверки разрешены вне анализируемого интервала.
- Режим отправки в этом варианте не предписан. По общей формулировке задания
  буферы неблокирующих операций нельзя изменять или использовать до завершения
  соответствующих запросов через Wait/Test.
- Процессы исправны, доставка надёжна и конечна; порядок сообщений одной пары
  сохраняется.
- Временная оценка должна учитывать зависимости и все служебные сообщения.
  Результат должен быть получен, связанные с ним запросы — завершены.

## Уточнения преподавателя

- Все массивы должны быть распределены. Полные копии входов на каждом процессе
  недопустимы. Итоговый массив у корня предусмотрен условием варианта.
- Требуется именно Open MPI.

## Материалы для сдачи

Исходный код и отчёт: описание алгоритма, временные оценки, команды сборки
и запуска, схема обменов или состояний.

На защите нужно самостоятельно объяснить программу и внести небольшое изменение
условий за 8–10 минут. До проверочного запуска фиксируется прогноз изменения
результата, трассы или времени.

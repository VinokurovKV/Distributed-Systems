# Базовый алгоритм слияния

Реализация: [merge.c](../src/merge.c). Генерация, проверка и измерения
выполняются отдельно от алгоритма в [main.c](../src/main.c).
Условия приведены в [assignment.md](assignment.md).

## Данные и предпосылки

Используются ровно восемь процессов Open MPI. Каждый процесс хранит собственный
неубывающий блок `local[N]` типа `int32_t`. `N ≥ 1` одинаково и известно всем
процессам до начала алгоритма. При передаче применяется `MPI_INT32_T`.

Первая последовательность — конкатенация блоков рангов 0, 1, 2, 3;
вторая — рангов 4, 5, 6, 7. Каждая конкатенация неубывает.
Полные входные последовательности ни на одном процессе не выделяются.

Корень 0 заранее выделяет `result[8N]` и два буфера `buffer_a[N]`, `buffer_b[N]`.
Свой исходный блок корень читает напрямую. Остальные исходные блоки не изменяются
и передаются непосредственно из памяти владельцев.

Для обычных MPI-вызовов с параметром `count` типа `int` требуется `N ≤ INT_MAX`.
Перед выделением памяти проверяются переполнения размера `8N` и размеров в байтах,
а также успешность выделения. Эти проверки и подготовка данных выполняются
до анализируемого интервала. Неверное число процессов и недопустимый `N`
отклоняются до запуска протокола.

## Состояние корня и выбор элемента

У каждого из двух потоков данных корень хранит:

- текущего владельца блока;
- позицию `pos` внутри блока;
- указатель на текущий загруженный блок либо признак, что его нужно запросить;
- признак полного исчерпания последовательности.

Первая последовательность начинает с владельца 0 и указателя на `local` корня.
Вторая — с владельца 4 и ещё не загружена. Отдельный счётчик `out`
указывает следующую свободную позицию результата.

Перед выбором очередного элемента корень обеспечивает наличие голов обоих
неисчерпанных потоков. Если нужный блок ещё не загружен, он запрашивается целиком.
Проверка первой последовательности выполняется перед проверкой второй,
поэтому порядок действий однозначен.

Далее:

1. Если первая последовательность исчерпана, берётся элемент второй.
2. Если вторая исчерпана, берётся элемент первой.
3. Иначе сравниваются текущие элементы. При `a ≤ b` берётся `a`, иначе — `b`.
4. Элемент записывается в `result[out]`; увеличиваются `out` и позиция
   только выбранного потока.

При равенстве выбирается первая последовательность. Элементы не удаляются
как дубликаты: каждое вхождение записывается отдельно.

Если позиция достигает `N`, текущий блок полностью использован:

- после владельцев 0, 1, 2 первая последовательность переходит к 1, 2, 3;
- после владельца 3 первая последовательность исчерпана;
- после владельцев 4, 5, 6 вторая переходит к 5, 6, 7;
- после владельца 7 вторая исчерпана.

Позиция сбрасывается в 0, предыдущий блок помечается как недоступный.
Новый блок запрашивается на следующем проходе перед выбором элемента.
Даже если другая последовательность уже исчерпана, оставшиеся блоки запрашиваются
в порядке владельцев и дописываются в результат.

Упрощённый псевдокод:

```text
A = поток владельцев 0..3, первый блок = local корня
B = поток владельцев 4..7, первый блок ещё не загружен
out = 0

пока out < 8N:
    обеспечить текущий блок A, если A не исчерпан
    обеспечить текущий блок B, если B не исчерпан

    если B исчерпан или (A не исчерпан и A.head <= B.head):
        result[out] = A.head
        продвинуть A
    иначе:
        result[out] = B.head
        продвинуть B
    out += 1
```

Условие выбора использует короткое вычисление логических выражений:
голова исчерпанного потока не читается. Пустой или ещё не принятый буфер
никогда не используется как источник элементов.

## Протокол точечных обменов

Для базовой версии выбран синхронный блокирующий режим `MPI_Ssend`
и блокирующий приём `MPI_Recv`. Все обмены выполняются в `MPI_COMM_WORLD`.
Подготовка и проверка не используют теги алгоритма.

| Сообщение | Источник → получатель | Тег | Состав | Длина | Условие отправки |
|---|---|---:|---|---:|---|
| REQUEST | 0 → r, r=1..7 | 100 | Пустой сигнал | 0 байт | Корню нужен ещё не полученный блок владельца r |
| DATA | r → 0 | 101 | N значений int32 | 4N байт | Владелец принял свой REQUEST |

Ранг владельца задан адресатом запроса и источником ответа. `N` заранее известен;
смещение всегда 0. Эти поля в полезной нагрузке не передаются.
Теги и адреса относятся к MPI-конверту, который отдельно не прибавляется к `m`:
внутренние MPI-согласования по условию включены в `Ts`.

Запрос блока у корня:

```text
MPI_Ssend(NULL, 0, MPI_BYTE, r, REQUEST, MPI_COMM_WORLD)
MPI_Recv(buffer, N, MPI_INT32_T, r, DATA, MPI_COMM_WORLD, ...)
```

Действия каждого владельца `r = 1..7`:

```text
MPI_Recv(NULL, 0, MPI_BYTE, 0, REQUEST, MPI_COMM_WORLD, ...)
MPI_Ssend(local, N, MPI_INT32_T, 0, DATA, MPI_COMM_WORLD)
вернуться из алгоритма
```

Принимающая сторона и тег заданы явно, `MPI_ANY_SOURCE` не требуется.
Корень начинает следующую пару REQUEST/DATA только после полного приёма
предыдущего DATA. Неполных ответов нет: все исходные блоки имеют ровно N элементов.
На корне нет активных неблокирующих запросов и не требуется `Wait`/`Test`.

## Завершение и отсутствие взаимоблокировки

У каждого удалённого владельца один блок, и весь его блок обязательно входит
в результат. Поэтому каждый владелец заранее знает, что обслуживает ровно
один запрос. После завершения `MPI_Ssend` его участие в алгоритме окончено.
Сигналы STOP, READY и ACK не используются.

Владелец сначала ожидает REQUEST. Это позволяет завершиться запросу корня.
Затем корень переходит к приёму DATA, что позволяет завершиться ответу владельца.
Цикла ожиданий нет. Остальные владельцы в это время ожидают собственных запросов.
Аргумент не зависит от наличия внутренних eager-буферов MPI.

Корень заканчивает после записи ровно `8N` элементов. Все семь ответов к этому
моменту приняты. В учебной модели локальные действия имеют нулевую стоимость,
поэтому завершение связанных операций не добавляет отдельной задержки.
Глобальный барьер внутри алгоритма не нужен.

При повторных запусках все процессы должны завершить предыдущий вызов алгоритма
до начала следующего; согласование повторов выполняется вне измеряемого интервала.
`MPI_Finalize` также находится вне него.

## Корректность

Перед каждым выбором доступны минимальные ещё не использованные элементы
обеих неисчерпанных последовательностей. Это следует из порядка элементов
в блоке и порядка самих блоков.

Выбирается минимум этих голов, поэтому очередной элемент не меньше предыдущего
и не больше любого оставшегося элемента. Если одна последовательность закончилась,
вторая уже упорядочена и может быть дописана в своём порядке.

Каждый шаг потребляет ровно один элемент только одного потока. Позиции
увеличиваются без пропусков; каждый блок загружается один раз. После `8N` шагов
все исходные вхождения находятся в результате ровно по одному разу.
Исходные блоки используются только для чтения, поэтому сохраняются неизменными.

## Запросы и полезные данные

Всегда запрашиваются семь удалённых блоков. Для блока ранга 0 обмен не нужен.

| Величина | Значение |
|---|---:|
| Прикладные запросы блоков | 7 |
| Ответы с данными | 7 |
| Всего прикладных сообщений | 14 |
| Переданные элементы | 7N |
| Полезные данные по сети | 28N байт |
| Явно переданные служебные поля | 0 байт |

Пустые запросы имеют нулевую длину, но ненулевую стоимость отправки.
Среди программ, передающих исходные int32 без сжатия или восстановления значений
по формуле, все `7N` внешних элементов должны попасть к корню. Базовая версия
передаёт каждый из них один раз. Это не утверждение об оптимальности числа
служебных сообщений среди всех возможных протоколов.

## Рабочая память

В таблице учитываются элементы последовательностей; скалярное состояние
алгоритма занимает дополнительно `O(1)` памяти.

| Процесс | Исходный блок | Итог | Дополнительные буферы | Всего элементов |
|---|---:|---:|---:|---:|
| Корень 0 | N | 8N | 2N | 11N |
| Каждый из 1..7 | N | 0 | 0 | N |

Для int32 это `44N` байт на корне и `4N` байт на каждом другом процессе,
плюс скалярное состояние. Суммарно — `72N` байт элементов на восьми процессах.
Дополнительные буферы корня занимают ровно `2N` чисел, у владельцев их нет.
Буфер первой последовательности выделяется отдельно, даже пока читается
собственный блок корня; оценка учитывает его целиком.

Внутренние структуры MPI не являются дополнительными массивами элементов
программы; пользовательские буферы для `MPI_Bsend` не используются.

## Полное время в модели S(8)

Обозначим порядок запрашиваемых владельцев через `q₁,…,q₇`.
Он зависит от входа; первым всегда запрашивается владелец 4.

Каждая пара REQUEST/DATA начинается после завершения предыдущей.
Локальное слияние между обменами имеет нулевую модельную длительность.
Поэтому здесь сумма стоимостей сообщений действительно равна полному времени:
нет параллельных передач или положительных локальных задержек.

| Событие пары k, k=1..7 | Начало | Конец |
|---|---|---|
| REQUEST: 0 → qₖ | (k−1)(200+4N) | (k−1)(200+4N)+100 |
| DATA: qₖ → 0 | (k−1)(200+4N)+100 | k(200+4N) |

Общая формула:

```text
T(N) = 7 · [τ(0) + τ(4N)]
     = 7 · [100 + (100 + 4N)]
     = 1400 + 28N условных единиц.
```

Например, `T(1)=1428`, `T(2)=1456`.
Изменение порядка значений меняет трассу владельцев, но не число сообщений,
объём данных и модельное время этой версии.

Фактическая локальная работа корня линейна: `8N` записей результата,
от `4N` до `8N−1` сравнений голов двух непустых последовательностей.
Реальное время Open MPI включает эти вычисления и свойства оборудования;
формула в условных единицах не является прогнозом секунд на компьютере.

## Сценарии для проверки протокола

Пусть `g=0,…,4N−1` — глобальная позиция внутри одной входной последовательности.
Каждый владелец формирует только свои N значений по этой позиции.
Формулы генерации должны вычисляться в достаточно широком типе с проверкой
диапазона int32 до запуска алгоритма.

| Сценарий | Первая последовательность A[g] | Вторая B[g] | Порядок запросов |
|---|---|---|---|
| Непересекающиеся диапазоны, A раньше B | g | 4N+g | 4, 1, 2, 3, 5, 6, 7 |
| Непересекающиеся диапазоны, B раньше A | 4N+g | g | 4, 5, 6, 7, 1, 2, 3 |
| Полное чередование | 2g | 2g+1 | 4, 1, 5, 2, 6, 3, 7 |
| Все элементы равны, в том числе на границах | 7 | 7 | 4, 1, 2, 3, 5, 6, 7 |

В первом сценарии блок 4 нужен уже для первого сравнения, даже если вся первая
последовательность впоследствии оказывается меньше второй.
В сценарии равных значений корень сначала выбирает все элементы A из-за `a ≤ b`,
а затем все элементы B. В результате должно остаться ровно `8N` семёрок.

Дополнительный сценарий с разными значениями и равенствами на каждой границе:
при `N ≥ 2` обе последовательности задаются как `A[g]=B[g]=floor((g+1)/N)`.
Значения на позициях `kN−1` и `kN` совпадают для `k=1,2,3`.
Отдельно проверяются `N=1`, отрицательные значения и крайние значения int32:
сравнение выполняется через `≤`, а не через вычитание, которое может переполниться.

## Проверка реализации

Каждый процесс формирует только свой исходный блок. После слияния он сравнивает
его с детерминированным генератором без резервной копии. Корень проверяет порядок
результата и независимо вычисляет позицию каждого исходного вхождения:
для `A[g]` это `g + lower_bound(B, A[g])`, для `B[g]` —
`g + upper_bound(A, B[g])`. Бинарный поиск обращается к генератору значений,
полные A, B и эталонный массив не создаются. Проверка требует `O(N log N)`
локальной работы и `O(1)` дополнительной памяти, выполняется вне интервала слияния.

Проверяются семь запросов, семь ответов, `7N` переданных элементов и посещение
каждого удалённого владельца один раз. Для сценариев с известным порядком
дополнительно проверяется точная трасса. Статистика считает отправки, поэтому
каждое сообщение учитывается ровно один раз при суммировании по процессам.

`make test` выполняет 72 случая: восемь сценариев на размерах 1, 2, 3, 7, 16, 31,
64 и 16 дополнительных seed для случайного сценария при N=17. Генератор `random`
даёт неубывающие последовательности с повторениями и псевдослучайными промежутками;
это воспроизводимые структурированные данные, а не произвольный внешний ввод.
Дополнительные сценарии — отрицательные значения и `INT32_MIN`/`INT32_MAX`.

Для безопасного диапазона всех генераторов CLI ограничивает N значением
`floor(INT32_MAX/8)`. Размеры выделяемой памяти проверяются отдельно.

`make run ARGS="4 alternating --trace"` выводит результат проверки,
число сообщений, объём данных, модельное время и трассу обменов. Трасса печатается
после слияния; её временные метки вычислены по модели, а не измерены через MPI.

У обычной программы только размер блока, сценарий и необязательный `--trace`.
Без аргументов используются N=16 и alternating. Начальное значение случайного
генератора задаётся константой `DEFAULT_SEED` в main.c. Самопроверка запускается
через `make test`, который собирает отдельную программу `merge_test` из тех же
исходников с определением `MERGE_SELF_TEST`.

Перед слиянием выполняется подготовительный барьер. Каждый процесс измеряет
только свой вызов алгоритма через `MPI_Wtime`; затем вне этого вызова собирается
максимальная длительность.

Чтобы ранние владельцы не начали коллективные операции проверки, пока корень
ещё сливает данные, проверочная оболочка использует отдельный сигнал DONE:
источник 0, получатели 1..7, тег 200, пустое содержимое. Корень отправляет эти
семь сигналов через `MPI_Ssend` только после готовности всего результата
и остановки своего таймера. Владельцы после остановки своих таймеров только
ожидают DONE через `MPI_Recv`, до этого ничего не отправляют для проверки.
Так первый обмен проверки начинается после окончания всего слияния.

Это семь дополнительных сообщений оболочки вне интервала алгоритма, отдельно
указанных в выводе. Их суммарная стоимость по шине — 700 условных единиц;
они не входят в `T(N)`. Коллективные операции подготовки и проверки также
находятся вне интервала слияния и не относятся к его 14 сообщениям.
Они не используются для получения самого результата. Выделение памяти,
генерация, независимая проверка результата и печать не измеряются.
